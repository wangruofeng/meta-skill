# 风格指南

## 核心原则

### 1. 通俗优先

根本问题用日常语言表述，避免用术语解释术语。新人能懂是第一目标。

- ✅ 「界面怎么渲染：数据 → 可见页面」
- ❌ 「视图层通过声明式范式实现 DOM 的响应式更新」

### 2. 重「为什么」轻「是什么」

解释每个东西存在的理由，而不是罗列功能。LLM 很聪明，理解了 why 能自己推导 how。

- ✅ 「TanStack Query 管'何时拿/怎么缓存'，因为服务器数据与 UI 状态有本质区别」
- ❌ 「TanStack Query 提供 useQuery、useMutation、QueryClient 等 API」

### 3. 类比要克制

类比是脚手架不是地基，用完要回到事物本身，避免类比失真。

- ✅ 「库 = 分工，就像公司里有人管销售、有人管财务」—— 然后立刻回到具体分工表
- ❌ 「React 就像乐高积木，TanStack Query 就像传送带」—— 类比过度且失真

### 4. 引用已有内容

搜索到的相关材料，用「你在 XX 里提到过...」引用，与通用知识区分开。这既尊重用户的已有认知，也避免重复讲解。

### 5. 避免空话

不要「这是一个非常重要的话题」「在现代开发中……」这类填充，直接给洞察。

### 6. 诚实标注边界

- 区分「事实」（可验证）和「推断」（基于证据的推测），推断要说明依据
- 主动指出不确定/有争议的部分
- 不为了显得深刻而强行拆解——约定俗成的内容直接说明即可
