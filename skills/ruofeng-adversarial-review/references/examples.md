# 示例

## 代码审查：信源抓取模块

输入：「审查一个信源抓取模块的健壮性」

输出：

```
# 信源抓取 对抗式审查报告

## 破坏目标
让抓取出错、崩溃、或污染信息流。

## 攻击总结
有缺口：OOM 死循环 + 未来时间污染 两个致命问题。

## 确认的威胁

### 🔴 OOM 死循环（致命 / 必然，一旦触发）
- 破绽：worker 处理超大 HTML 时内存爆 → 被系统杀 → 自动重试 → 同一个大任务再爆 → 无限循环
- 证据：worker 无内存上限 + 无重试次数限制 + 自动重试机制
- 攻击路径：我提交一个 50MB 的 HTML，worker 必爆，重试必再爆，循环至耗尽资源
- 加固：限制单任务输入大小 + 重试退避上限 + 识别「必爆任务」标记不再重试

### 🔴 未来时间污染（严重 / 偶发）
- 破绽：信源文章发布时间因时区错误显示成「未来」→ 时间戳最新 → 排到信息流最前 → 进 PUSH/RSS/日报
- 攻击路径：一个时区 bug 让某文章 time = 明天，全信息流被这一篇污染
- 加固：发布时间 > now 的条目，钳制到 now 或丢弃

## 排除的伪问题
- HTML 解析慢？否，流式解析 + 超时控制已覆盖
- 网络抖动导致丢数据？否，指数退避重试 + 持久化队列
- 多 worker 重复抓取？否，分布式锁 + 幂等去重

## 未覆盖的攻击面
未查权限模型、未做并发压力测试、未审计第三方 HTML 解析库的 CVE。

## 加固优先级
1. 加输入大小限制 + 重试退避上限
2. 加未来时间钳制
3. 补充权限审计
```
