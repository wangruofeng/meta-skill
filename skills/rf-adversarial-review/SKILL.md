# /rf-adversarial-review — 对抗式审查

强制站到对立面，主动构造攻击向量击穿审查对象，而不是顺向确认它没问题。设计哲学见 [references/philosophy.md](references/philosophy.md)。

## 输入

`$ARGUMENTS`：代码（文件路径/目录/片段）、文章/文档（路径/URL/文本）、方案/决策描述、或一个系统/功能。输入为空时，让用户指定审查对象。

## 执行步骤

1. **明确破坏目标**：识别对象类型与核心主张/关键路径，明确「什么坏了算找到问题」（代码：崩溃/数据错/安全洞；论证：逻辑断裂/事实错/反例成立）。可 Grep 当前目录已有内容作攻击弹药。
2. **构造攻击向量（核心）**：从六个正交维度枚举「怎么搞垮它」——①极端输入 ②边界与并发 ③失败与恢复 ④恶意与滥用 ⑤逻辑与事实 ⑥时间与演化，每个向量落到可执行的破坏场景。按对象选维度：代码/系统用 1-4，文章/论证用 5-6，方案/决策用 5-6 + 风险清单。详见 [references/attack-vectors.md](references/attack-vectors.md)。
3. **走通攻击路径，验证真伪**：对每个向量实际走一遍破坏过程，区分真威胁（路径走得通、有证据）与伪问题（被防护层挡住或概率极低），评估严重度（致命/严重/一般）与触发概率（必然/偶发/罕见）。宁可少而准，不要多而虚。
4. **输出攻击报告**：对每个确认的真威胁——破绽 → 证据 → 后果 → 最小可行加固。
5. **标注审查边界**：明确已覆盖 vs 未覆盖的攻击面，区分确定 bug 与疑似待验证。

## 输出结构

依次输出：**破坏目标** → **攻击总结**（一句话：能扛/有缺口/脆弱）→ **确认的威胁**（按严重度排序，每条含破绽/证据/后果/加固）→ **排除的伪问题**（≥3 条，避免误导）→ **未覆盖的攻击面**（必填）→ **加固优先级**。

完整报告示例见 [examples/review-report.md](examples/review-report.md)。
