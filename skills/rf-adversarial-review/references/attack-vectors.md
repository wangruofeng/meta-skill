# 攻击向量详解

六个正交的攻击维度及每个维度的典型破坏场景。

## 1. 极端输入：「喂 abnormal 数据」

| 攻击场景 | 典型输入 | 期望破坏 |
| --- | --- | --- |
| 超大输入 | 50MB HTML、10000 行 CSV | OOM、CPU 耗尽 |
| 空/缺失 | null、空字符串、缺失字段 | NPE、逻辑跳过 |
| 负值/零 | -1、0、负数金额 | 除零、负库存、无限循环 |
| 特殊字符 | 零宽空格、RTL 覆盖符、emoji | 解析异常、显示混乱 |
| 未来/过去时间 | 2099-01-01、1970-01-01 | 排序错乱、缓存永不过期 |
| 类型错配 | 字符串给数字字段、数组给对象 | 类型转换异常、静默错误 |

## 2. 边界与并发：「卡在缝里」「同时来」

| 攻击场景 | 典型输入 | 期望破坏 |
| --- | --- | --- |
| Off-by-one | 刚好等于阈值、阈值±1 | 越界访问、漏掉/多出一条 |
| 并发竞态 | 两请求同时读写同一资源 | 数据覆盖、状态不一致 |
| 时序依赖 | A 必须在 B 之前完成，但 B 先到 | 逻辑错乱、空指针 |
| 时区/编码 | UTC+14 到 UTC-12、夏令时边界 | 时间计算错误、排序错乱 |
| 空集合 | 空列表、空文件、无结果 | 除零、空指针、UI 崩溃 |

## 3. 失败与恢复：「半路断了怎么办」

| 攻击场景 | 典型输入 | 期望破坏 |
| --- | --- | --- |
| 超时 | 网络延迟 30s+ | 连接池耗尽、请求堆积 |
| 部分失败 | 批量操作中第 3 条失败 | 事务不一致、部分生效 |
| 依赖挂掉 | 数据库/缓存/第三方 API 不可用 | 雪崩、全链路失败 |
| 重试风暴 | 失败后无限重试无退避 | 资源耗尽、下游被打垮 |
| 幂等性 | 同一请求重复发送 | 重复扣款、重复创建 |
| 中断恢复 | 进程在操作中途被杀 | 数据不一致、任务丢失 |

## 4. 恶意与滥用：「故意搞你」

| 攻击场景 | 典型输入 | 期望破坏 |
| --- | --- | --- |
| 注入 | SQL/命令/模板注入 | 数据泄露、远程执行 |
| 越权 | 修改请求中的 user_id | 访问他人数据 |
| 资源耗尽 | 死循环输入、zip bomb | OOM、CPU 打满 |
| 速率绕过 | 分布式请求绕过单 IP 限流 | 暴力破解、爬虫 |
| 输入伪装 | 超长字符串伪装正常输入 | 存储撑爆、索引退化 |

## 5. 逻辑与事实：「前提真的成立吗」

| 攻击场景 | 典型检查 | 期望破坏 |
| --- | --- | --- |
| 隐含前提 | 「所有人都需要 X」——真的吗？ | 方案根基不成立 |
| 因果倒置 | 「用户增长是因为改版」——还是自然增长？ | 归因错误 |
| 幸存者偏差 | 「成功公司都这样做」——失败的也这样做了吗？ | 错误模式识别 |
| 数据可信度 | 来源是二手报告还是原始数据？ | 基于错误信息的决策 |
| 反例构造 | 找一个场景让方案的核心逻辑失效 | 方案边界暴露 |

## 6. 时间与演化：「以后会怎样」

| 攻击场景 | 典型检查 | 期望破坏 |
| --- | --- | --- |
| 规模失效 | 10x 用户量后还能工作吗？ | 性能崩塌、架构重构 |
| 依赖过时 | 核心依赖 2 年不维护了 | 安全漏洞、无法升级 |
| 技术债累积 | 当前方案阻止了未来的 X 需求吗？ | 锁定效应、迁移成本 |
| 场景演化 | 如果用户行为模式改变会怎样？ | 方案核心假设失效 |

## 使用原则

- 不是每个对象都要用全部六个——按类型选最相关的
- 每个攻击向量要落到**可执行的破坏场景**，不是泛泛的「可能有并发问题」
- 越具体越能逼出真问题：从入口出发，沿执行链走通整个破坏过程
