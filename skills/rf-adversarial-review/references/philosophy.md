# 对抗式审查：设计哲学

## 什么是对抗式审查

顺向审查 = 站在作者这边检查，天然倾向**确认偏误**（倾向于证明它是对的，下意识忽略问题）。对抗式审查 = **强制立场对立**，把自己当成要搞垮它的对手，主动构造攻击向量。

## 为什么需要对抗而不是顺向

人（和 AI）在检查自己/同类的东西时，会有强烈的「确认偏误」——倾向于看到「能用」「差不多」「没问题」。真正危险的缺陷，几乎都不在「正常使用」的路径上，只在「极端输入」「恶意使用」「边界情况」里暴露。顺向审查走的是正常路径，所以看不见它们；对抗式审查专门走异常路径，所以能逼出它们。

## 与第一性原理的对称关系

`rf-adversarial-review` 管**验证**——让产出能扛住真实世界的攻击和意外。配套的 `rf-first-principles` 管**生成**——让方案从根本事实出发、方向正确。

- 只用第一性原理不用对抗审查 → 方向对但健壮性差，上线即翻车
- 只用对抗审查不用第一性原理 → 能扛打但方向可能就是错的

合起来是完整的「生成 → 验证」闭环。
