# 多 Agent 对抗审查

对抗式审查的威力与**对抗密度**正相关。单个审查者仍受限于一个视角，会有盲区。对重要对象，建议并发启动多个 agent 各自扮演不同攻击者。

## 使用方式

在任何支持并发 agent 的平台上（如 Claude Code），对重要审查对象触发多 agent 模式。每个 agent 分配不同攻击维度或人设，最后汇总去重按严重度排序。

## 典型 Agent 分工

| Agent 角色 | 分配维度 | 专攻什么 |
| --- | --- | --- |
| 并发猎人 | 边界与并发（维度 2） | 竞态、时序、锁 |
| 恶意用户 | 恶意与滥用（维度 4） | 注入、越权、资源耗尽 |
| 输入破坏者 | 极端输入（维度 1） | 超大/空/畸形输入 |
| 故障工程师 | 失败与恢复（维度 3） | 超时、断连、重试风暴 |
| 逻辑对手 | 逻辑与事实（维度 5） | 隐含前提、反例、数据可信度 |
| 未来悲观者 | 时间与演化（维度 6） | 规模失效、依赖过时 |

## 为什么有效

不同视角的攻击者盲区不重叠，并发能把单视角漏掉的问题补上。一个 agent 漏的，另一个会抓到。这比单 agent 顺查一遍严格得多。

## 输出汇总

多 agent 完成后，汇总去重：
1. 合并所有 agent 的威胁列表
2. 去重（同一威胁被多个 agent 发现，保留最详细的描述）
3. 按严重度重新排序
4. 标注每个威胁的发现者（哪个 agent 角色发现的），帮助理解盲区分布
