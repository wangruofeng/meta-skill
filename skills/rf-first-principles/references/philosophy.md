# 第一性原理：设计哲学

## 什么是第一性原理

第一性原理源自物理学，指「回归到最基本的、不能进一步被推论的真理，再从这里向上推理」。在本 skill 里它具体化为三个动作：

1. **剥离表象**：忽略术语、惯例、类比、「别人都这么做」的包装，追问「这里真正在解决什么问题」。
2. **找到根本问题**：把任何系统/概念拆成少数几个不可再分的根本问题。复杂系统 = 少数根本问题的组合。
3. **从根本重建**：从这些根本问题出发，重新理解每个组成部分为什么存在、它占了哪一格。

## 为什么这有效

人的认知天然倾向记忆「答案」而非「问题」。但答案会变（库会更新、框架会过时），根本问题却稳定（Web 应用永远要回答「界面怎么渲染」「数据怎么拿」）。抓住根本问题，新答案出现时你能自动归类，而不是重新学一遍。

## 根本问题的判断标准

一个好的「根本问题」满足三个条件：

- **不可再分**：再往下拆就不再是「问题」而是「实现细节」。
- **正交**：与其他根本问题不重叠，彼此独立。
- **完备**：合在一起能覆盖整个领域的核心逻辑。

通常一个领域有 3-7 个根本问题。超过 7 个通常意味着混入了非根本问题；少于 3 个可能说明领域本身不够复杂，或拆解得不够。

## 常见领域示例

- **Web 应用**：界面怎么渲染、路由怎么走、数据怎么拿/存、状态怎么记、样式怎么写、怎么构建/部署（6 个）
- **一家公司**：创造什么价值、卖给谁、怎么收费、怎么防御竞争（4 个）
- **一段论证文章**：核心主张是什么、基于什么前提、推理链条、反例与边界（4 个）
- **编程语言**：怎么表达计算（语法）、怎么组织代码（模块/类型）、怎么管理内存、怎么并发、怎么互操作（5 个）

## 与对抗式审查的对称关系

`rf-first-principles` 管**生成**——让方案从根本事实出发、方向正确。配套的 `rf-adversarial-review` 管**验证**——让产出能扛住真实世界的攻击和意外。

- 只用第一性原理不用对抗审查 → 方向对但健壮性差，上线即翻车
- 只用对抗审查不用第一性原理 → 能扛打但方向可能就是错的

合起来是完整的「生成 → 验证」闭环。
